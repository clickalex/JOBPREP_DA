# ShopKart data dictionary

ShopKart is a **fictional** Indian e-commerce marketplace (prices in INR). All data is generated by
[`generate_data.py`](generate_data.py) with a fixed seed, so everyone gets identical numbers. It is synthetic, but it
behaves like real data. Hidden in it are patterns worth finding:

* growth over time plus a **Diwali spike** every October
* acquisition channels with very different **retention**
* categories with different **margins** and **return rates**
* higher **cancellations for Cash on Delivery**
* a **regional logistics incident** somewhere in 2025 (SQL Q34 asks you to find it)
* a **checkout A/B test** whose effect isn't the same for every device
* a price increase at the start of FY26 (1 April 2025)

```bash
python data/generate_data.py   # rebuilds clean/, raw/ and shopkart.db (~5 seconds)
```

## Tables

### `customers` (8,000 rows)
| Column | Type | Notes |
|---|---|---|
| customer_id | int PK | 10001… |
| first_name, last_name, email | text | |
| gender | text | F / M |

### `order_items` (20,298 rows)
| Column | Type | Notes |
|---|---|---|

### `web_sessions` (40,000 rows, Jul–Dec 2025)
One row per website/app session with funnel flags (`viewed_product`, `added_to_cart`, `began_checkout`,
`purchased`, each 0/1), `device`, `traffic_source` and `pages_viewed`. `customer_id` is NULL for anonymous visitors.

### `checkout_experiment` (24,000 rows, 1–28 Sep 2025)
| Column | Notes |
|---|---|
| visitor_id | unique visitor |
| variant | `A_control` or `B_new_checkout` (random 50/50) |
| device | Mobile App, Mobile Web, Desktop |
| assigned_at | timestamp |
| converted | 1 if the visitor ordered |
| order_value | INR, 0 if not converted |

### `employees` (30 rows)
`employee_id`, `full_name`, `department`, `manager_id` (NULL for the CEO), `hire_date`, `monthly_salary`.
Includes salary ties, for RANK vs DENSE_RANK questions.

## Standard metric definitions

Every exercise and the portfolio project use these definitions. Agreeing on definitions is half of real analytics work.

| Metric | Definition |
|---|---|
| Net line revenue | `quantity * unit_price - discount` (excludes shipping) |
| Valid order | `status IN ('Delivered', 'Shipped')` |
| Net revenue | sum of net line revenue over valid orders |
| AOV | net revenue ÷ distinct valid orders |
| Gross margin % | (net revenue − Σ quantity × unit_cost) ÷ net revenue |
| Cancel / return rate | cancelled (returned) orders ÷ all orders |
| Conversion rate | purchases ÷ sessions (or converted ÷ visitors in the experiment) |

## The raw files: what's wrong with them?

Try to find the problems yourself before reading this list:

<details><summary>Spoiler: known issues</summary>

* `customers_raw.csv`: exact duplicate rows; near-duplicates with trailing spaces in `first_name`; city variants (`Bangalore`, `NEW DELHI`, `Bombay`, `Gurgaon`, `Calcutta`, `Madras`, stray whitespace); `signup_date` in three formats (`2024-03-05`, `05/03/2024`, `05 Mar 2024`); upper-case emails; missing emails and channels; no `region` column.
* `orders_raw.csv`: duplicate rows; `status` in mixed case with trailing spaces; `payment_method` variants (`COD`, `cod`, `upi`, `CC`, `DC`…).
* `order_items_raw.csv`: negative quantities; 15 prices entered in paise (100x); 25 missing prices; blank discounts.

</details>
